# 票屿使用说明

本地发票管理工作台：扫描和导入发票、核对信息、记录报销状态、处理重复票据，生成科研材料入库单及配套统计表格。浏览器界面和 SQLite 数据库都运行在自己的电脑上，日常使用不需要账号、API Key 或云服务。

## 功能

- 导入 PDF、PNG、JPG 和 ZIP；支持指定发票文件夹、子目录扫描和目录排除。
- 按票号或文件内容识别重复项，统计不重复计入金额；跨页全选、筛选、排序及搜索。
- 手动修改票据信息；发票类型通过固定下拉选择，记录变更前后及时间。
- 发票分类包括其他票据、出行交通、科研材料、铁路客票、住宿费；筛选按此顺序显示，尚无票据的分类也可选择。
- 新票据初次导入按票种和商品内容分类，混合 ZIP 逐张判断；科研材料支持摄像头、PLA 等关键词，保留之后的人工分类。
- 行程单附件不显示在发票列表，不参与统计、去重及台账导出，保留原文件和已有记录。
- 勾选发票后实时显示去重合计，跨页选择一并计算。金额未填写时显示已知合计及待填张数。
- 批量标记待报销或已报销。右侧红色“删除选中”需二次确认，文件随后移入可恢复的本地回收站。
- 恰好勾选两张往返铁路客票时，可按乘车日期和发车时间计算出差天数。当天往返计 1 天。跨日按日历计，晚间出发扣除出发日，晚间默认从 18:00 起算，可在计算窗口调整。
- 回收站可一键清空，永久删除前再次确认数量；文件被占用等失败条目保留并支持重试。
- 勾选一张可下载原件，勾选多张可导出 ZIP。ZIP 文件名包含张数、总金额及日期。另可导出 CSV 台账和数据库备份。
- 勾选发票后批量打印，支持跨页选择、完整多页 PDF 及图片；全部页面准备完成后统一打开打印窗口。
- 科研材料 PDF 一键生成入库单及统计表格；识别失败后可补填或直接生成，允许缺失字段留空；草稿可恢复。
- 统计表类别只能选择试剂、仪器或耗材；公司自动识别销售方并允许修改，网址和安全等级默认留空，安全等级仅供试剂填写。
- 适配分层文字、旋转水印、相连数字、高精度单价及可逐项归属的商品折扣。整批中某张识别失败时，其他张的识别结果仍可用于补填。
- 入库单列表只显示本工作台生成的成品，保留最近五组入库单和统计表格；项目名称和代码保留两行空白，供使用者填写。
- 统计表编辑窗口的标题和关闭按钮固定在顶部，滚动长表单时仍可关闭。
- 四种界面风格一键切换并记忆，文字至少 14px。

## 下载和启动

主要面向 Windows 10/11。需要 Python **3.10 或以上**，安装时勾选 **Add Python to PATH**。Node.js 仅用于前端开发测试，日常使用不需要。

1. 点击仓库页面 **Code → Download ZIP**，解压到普通文件夹；也可以用 Git 克隆。
2. 首次使用双击 **安装依赖.cmd**。它在项目内创建 `.venv`，从 PyPI 安装依赖，需要联网。可使用已有兼容虚拟环境跳过此步。
3. 双击 **启动工作台.cmd**，浏览器自动打开 `http://127.0.0.1:18626/`，启动窗口随后自动关闭，服务在后台运行。也可双击 **启动工作台.vbs**，全程不显示命令行窗口；需要桌面入口时，为这个 VBS 文件创建桌面快捷方式。
4. 将票据放进项目的 `invoices` 文件夹，再点击扫描；或进入 **本地设置 → 发票目录** 指定已有文件夹，也可直接导入。

完成安装后，管理发票和生成入库单可离线运行。不需要 Codex、Word 或单独安装 ruku 技能；入库单脚本已经随项目附带。

终端启动方法：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app\server.py
```

需要换端口或排除目录时：

```powershell
.venv\Scripts\python.exe app\server.py --port 18627 --ignore-dir "D:\MyInvoices\generated"
```

`--ignore-dir` 可重复指定，每次启动需传入。也可给 CMD 启动脚本传入相同参数。服务只监听 `127.0.0.1`，不用于公网部署。关闭浏览器不会停止服务；退出请在本地设置中点击“停止服务”。再次双击启动器会复用本目录已有服务。终端直接运行 `app/server.py` 时仍在前台运行，可按 Ctrl+C 退出。

后台日志保存在 `app/data/server.log` 和 `app/data/server-error.log`。启动失败时 CMD 入口显示错误并等待查看，VBS 入口弹出提示。更换端口可使用 `启动工作台.cmd --port 18627`；其他工作台占用同一端口时会提示冲突，不会关闭对方的服务。

macOS/Linux 可以安装依赖后运行 `python app/server.py`，在设置中手动粘贴目录路径；Windows 文件夹选择与“打开目录”按钮属于 Windows 功能。此项目的桌面启动脚本主要在 Windows 验证。

## 数据在哪里

| 内容 | 默认位置 |
| --- | --- |
| 初始发票目录 | `invoices/`，可在设置中更改 |
| 数据库和修改记录 | `app/data/invoices.sqlite3` |
| 导入副本与预览 | `app/data/imports/`、`app/data/previews/` |
| 回收站 | `app/data/trash/` |
| 入库单任务、草稿及成品 | `app/data/receipts/` |

切换发票目录保留旧台账和原票位置。批量标记报销状态后，点击列表右上角“撤销上次标记”可恢复各张票据的原状态。工作台记录最近一次批量标记，刷新后也可撤销。用户确认删除后，所选原件移到回收站。生成入库单使用独立副本，保留最近五组生成结果，每组包括入库单及统计表格。成品列表只显示从工作台生成的文件。

在回收站点击“清空回收站”会显示数量和不可恢复提示，默认聚焦取消；确认后永久删除本次确认时列出的回收站文件，不影响正常票据或生成文档。失败条目留在回收站，可重试；数据库保留删除标记和操作记录，避免重复扫描或重复导入同一 ZIP 时自动恢复已清空票据。

升级前备份 `app/data/` 及自己的发票目录，再替换程序源码。数据库备份不包含所有原始票据和生成文件，完整备份请保留这些目录。Git 忽略规则会排除本地数据，但提交前仍应查看 `git status`，不要使用 `git add -f` 强行加入票据。

## 识别和入库单

自动识别读取 PDF 文字层；图片和扫描件没有自动 OCR，需要手动填写。提取失败可展开“补填发票信息”，默认显示品名、型号（规格）、单位、数量和不含税金额，其余字段选填。所有字段为空也允许继续生成，未知内容在 Word 中留空。

初次导入优先按票面内容分类：铁路电子客票归铁路客票，住宿费归住宿费，客运、打车、停车或通行费归出行交通；试剂、实验仪器、电子配件、线缆、摄像头、PLA 等材料线索归科研材料。无法明确判断或明确混合多类的票据归其他票据。票面内容优先于文件名和目录，不根据购销方名称或备注推断类型；酒店开具的餐费仍归其他票据。PLA 匹配不区分大小写，支持 PLA+ 和带品牌前缀的独立词。分类只在新增记录时执行，旧台账及人工改类不会自动重算，类型修改历史保留。

新导入 PDF 即使票号、日期、总额齐全，也尝试按坐标核对商品名称；成功通过整单校验后，用名称列生成标题，避免把单位或规格混入品名。不自动重写旧人工标题。

行程单附件通过文件名、标题和文档开头识别，重复扫描或 ZIP 再次导入也会从发票页面排除。明确带电子发票或增值税发票抬头的文件仍显示，备注中提到行程单不会单独导致隐藏。此规则只改变列表可见性，不删除文件或台账记录。

金额合计、数字格式、文件来源与文件变化仍会检查。单价接受有效非负高精度数字；单商品采用票面价税合计，多商品在金额和税额完整时核对合计。成品采用浙江大学科研材料入库单模板，使用者应按自己的单位要求核对，并填写项目及签字栏。替换模板前请阅读 [架构说明](ARCHITECTURE.md)。

自动提取后会核对数量、单价及金额，有疑点时按 PDF 横向字符位置重建并排除旋转水印。可逐项归属的折扣按票面行序匹配商品，入库单和统计表均采用折后含税金额。归属不明确或金额有冲突时进入补填。旧失败任务重新打开补填也使用当前识别流程，已经保存的人工草稿会保留。

统计表与入库单来自同一份商品数据，可从生成结果下载或点击“编辑统计表格”修改类别、用途、公司、网址、安全等级及备注。名称和含税价格保持与入库单一致，底部不追加说明。统计表生成失败时已完成的入库单仍可下载，稍后可单独重试。旧表中的空白商品需重新生成才能采用新的识别结果。更新内容见 [更新记录](CHANGELOG.md)。

入库单和统计表的下载名采用“类型_金额_保存日期”的格式，如 `入库单_120.50元_2026-11-16.docx`。

## 导出和批量打印

勾选需要处理的发票，可以跨页选择或使用表头全选。单张时操作栏显示“下载原件”，多张时显示“导出 ZIP”。也可以点击“批量打印”。

ZIP 文件名示例：`发票_2张_总金额69.12元_2026-11-04.zip`。同张发票的重复副本只累计一次金额；部分金额缺失时标注已知金额和待填写张数，全部未填写时显示“总金额待填写”。打包仍保留每个选中文件。

批量打印按勾选顺序准备原票，每个原始页面单独放在一张 A4 纸上，多页 PDF 完整保留，图片按方向显示。页面全部加载成功后弹出浏览器打印窗口，选择打印机、份数并确认；若浏览器未自动弹出，可点击预览页的“打印”。请允许工作台打开新窗口。原件缺失、变化或读取失败时停止准备并提示，返回工作台处理后重试。取消系统打印对话框后，预览页可保留并再次打印。

准备和渲染均在本机完成，使用 200 dpi 打印页面，不保存额外票据副本、不改变台账或原文件。浏览器负责最终打印排版与打印机选择；打印对话框里的页眉和页脚可按需取消。

## 一起改进

欢迎提交 Issue 和 Pull Request。推荐流程是 **Fork → 创建分支 → 修改和测试 → 向本仓库提交 Pull Request**；维护者审阅后合并。详细步骤见 [贡献指南](../CONTRIBUTING.md)。不要在 Issue、PR 或截图中附上真实发票和本地数据库。

```powershell
python -m pip install -r requirements-dev.txt
cd app
python -m unittest discover -p "test_*.py" -v
node test_ui_filters.cjs
node test_import_history.cjs
node test_trip_days.cjs
node test_themes.cjs
node test_receipt_polling.cjs
node test_empty_trash.cjs
node test_export_zip.cjs
node test_invoice_print.cjs
```

项目采用 Python 标准库 HTTP 服务、SQLite 和原生 HTML/CSS/JavaScript，无前端构建步骤。测试使用隔离临时目录和合成数据。GitHub Actions 对提交和 Pull Request 自动运行回归。

# 架构与维护

## 目录

```text
app/
  server.py             本地 HTTP 接口、SQLite、扫描、导入、删除恢复及导出
  receipt_jobs.py       入库单任务、隔离副本、草稿与失败恢复
  receipt_layout.py     模板空段整理及缺失字段留空
  folder_picker.py      Windows 文件夹选择窗口
  web/                  原生前端，静态文件直接提供，无构建步骤
  assets/               空白入库单模板和启动图标
  vendor/ruku/          MIT 上游脚本、许可、来源和 SHA256
  test_*.py             隔离的后端回归
  test_*.cjs            前端行为回归
  data/                 运行生成，不入库
invoices/               默认票据目录，实际内容不入库
```

## 运行边界

服务绑定回环地址，变更接口检查 Host、Origin 和每次进程随机生成的工作台密钥。应用不是多用户财务服务器，不要将监听地址改成公网地址后直接部署。没有登录系统，也没有联网识别或遥测。

SQLite 保存字段和操作历史。文件原文保留在原位置，手动导入副本在 data/imports。回收站使用软删除记录和文件移动，恢复时检查目标冲突；批量操作先验证全部输入，再执行带回滚的变更。ZIP 只打包明确选择的原件，校验哈希和体积，同名文件添加编号。

启动先取得独占端口，再初始化数据库，避免重复启动重置运行任务。启动失败会释放连接；旧入库单被占用时显示维护提示，其他功能继续可用。

## 入库单

默认使用仓库内置的三个 ruku 脚本，顺序为提取、重命名、填表，均在 `app/data/receipts/<任务>/` 的独立副本中执行。识别失败时用户可以补填或将缺失值留空后继续。续跑保留识别原文和草稿，用兼容 JSON 调用原脚本，完成后清空文档中的未知占位值。任务状态、补填草稿和操作记录保持一致；线程启动失败可重试。

替换模板必须保留 OOXML 结构：首个表格含项目标题及两个空白项目行；第二表格用于商品、合计和签字。`receipt_layout.py` 与上游 fill_receipt.py 的单元格索引依赖这些结构。不能将任意 Word 表格直接替换为模板。

列表及下载接口只使用成功生成且成品仍存在的任务记录，不递归扫描当前或历史发票目录中的 DOCX；模板、测试文档和手工文件不列入。生成结果仅保留最近五份；只清理生成器自己的任务目录，其他用户文档保留。定期完整备份 data 和发票目录；只有数据库备份不足以恢复所有文件。

## 发布前检查

运行所有 Python 和前端回归，审查将提交的文件清单。不要发布 data、invoices 实际内容、带真实票据的截图、浏览器下载、验收记录、原始识别 JSON、个人绝对路径或凭据。更新模板时检查 DOCX 内部属性、外部链接、批注和缩略图是否含个人信息。
